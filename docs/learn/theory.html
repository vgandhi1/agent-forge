Part 01 · Theory

The theory of agentic systems

Seven ideas, framework-agnostic. Each one becomes concrete in Part 02 · In AgentForge.

① The loop ② Tool use ③ Planning ④ Memory ⑤ Multi-agent ⑥ Guardrails ⑦ Evaluation
① The core loop

The loop is the engine

Strip an agent to its core and you get a turn-based loop. The model proposes an action (usually a tool call); the runtime executes it; the result is fed back; repeat. Step through one agent fixing a failing test:

Perceive
Read state
Decide
Plan action
Act
Call tool
Observe
Read result
// press “Step the loop” to watch an agent fix a failing test…
turn 0
Why turns matter. A single model call can't both write ten files and verify them. The loop lets a model complete a large job across calls — write, observe, continue. Without it you have a one-shot generator, not an agent.
② Tool use & grounding

Tools are the agent's hands

An LLM alone only predicts text. Tools turn that text into action — and ground the agent in reality so it can verify its own work instead of hallucinating success.

perceive

Read tools

Inspect the world: read files, list, search — before changing anything.

act

Write / edit / run

Change the world: write or surgically edit files, run the test suite.

verify

Observe results

Read tool output — a failing assertion, a lint error — and react.

Grounding beats fluency. The most common agent failure is confidently reporting success it never verified. Tools that run and read the result are the antidote: the agent must face reality each turn.
③ Planning & adaptive control

Decide the steps, then revise them

A fixed pipeline is a recipe. An agent writes its own recipe from the goal — then rewrites it when a step fails. Three behaviours, each bounded so it can't spiral:

plan

Propose

Turn the goal into a sequence of steps.

re-route

Adapt

Insert a follow-up step when reality disagrees — within a budget.

verify

Self-check

Confirm the goal is actually met before declaring done.

Bounded autonomy is the whole game. Unbounded self-direction is how agents burn money and loop. Budgets, caps, and a hard stop are what make autonomy shippable.
④ Memory & the context budget

Working memory is finite — curate it

An agent's working memory is its context window. Long loops drown in their own history (the “lost in the middle” effect), so a production agent must decide what to carry forward.

persist

Durable log

Decisions and artifacts are stored outside the window and replayed selectively.

bound

Rolling summary + circuit breaker

Keep recent detail verbatim, condense the rest; drop the oldest exchanges before overflowing.

Three tiers of memory. Working (the live context window), episodic (this run's decisions log), and long-term (across runs — vector retrieval, still emerging). Good agents move information between tiers instead of cramming everything into one.
⑤ Multi-agent orchestration

From one agent to an org

One agent juggling every concern loses focus. Splitting work across specialists — each with its own persona, tools, and prompt — mirrors how human teams scale. A Lead coordinates; an independent Reviewer audits so the builder can't grade its own homework.

Communication patterns you'll meet in agentic orgs:

  • Blackboard / shared store — agents read and write a shared artifact space, referenced by path.
  • Message bus — agents publish to mailboxes instead of calling each other directly (loose coupling).
  • Request / response — the orchestrator consults the reviewer synchronously at each gate.
  • Handoff + checkpoint — durable handoffs make a long run resumable after a crash.
Independent review is a trust mechanism. If the agent that wrote the code also approves it, “done” means nothing. A separate reviewer that reads the real files — where silence ≠ approval — is what makes multi-agent output trustworthy.
⑥ Reliability & guardrails

Why production agents need brakes

Autonomy without guardrails is a liability: agents over-reach scope, approve their own work, hallucinate dependencies, and loop. Reliability is what turns a demo into a system you'd run unattended.

focus

Scope lock

Out-of-scope findings are logged and deferred, not silently absorbed into the task.

ask

Escalation + safe-pause

Ambiguity routes to a human; if no one answers in time, it pauses safely instead of guessing.

ship

Deploy gate

verify → human go/no-go → commit. Nothing ships that doesn't pass the project's checks.

cap

Budgets & caps

Replan budget, phase cap, revision cap, context breaker — the cost and safety brakes.

One brake is missing from this list: knowing the agent is actually good. That's evaluation → keep reading.
⑦ Evaluation

How do you know it's working?

An agent can pass every structural check and still be getting worse. The hardest problem in agentic systems isn't building the loop — it's measuring quality when outputs are open-ended and non-deterministic.

trap

The evaluation disconnect

Tests with faked model calls verify plumbing deterministically — but a change can stay green while silently degrading the actual prompts. The fake never notices.

fix

LLM-as-a-Judge

Use a second, cheaper model to grade the artifact against an explicit rubric (1–5 per criterion). Now prompt-quality regressions become a number you can track.

Two layers, two questions. Deterministic tests ask “do the parts still work?” — fast, free, run on every commit. Judge / live evals ask “is the output actually good?” — costly and noisy, so they run gated/nightly. You need both; neither replaces the other.
