Overview

What AgentForge is

A multi-agent software-engineering orchestrator (Python 3.11+). A Lead drives a team of specialists through a software lifecycle while an independent Reviewer audits the real files at every phase. It builds greenfield apps or operates on an existing repo via --target-repo.

// THEORY → goal-directed autonomy

“Given an objective, the system chooses steps itself.”

// AGENTFORGE → --adaptive

The Lead plans the phase sequence, re-routes on outcomes, and self-checks the goal — instead of running a static list.

⑤ Multi-agent, realized

The agent org

Agents never call each other directly — they publish to a priority MessageBus (one mailbox per role). The Lead orchestrates; the Reviewer gates.

① ② The loop & tools, realized

One loop, composable tool belts

Every agent shares BaseAgent.run_tool_loop — the multi-turn call → execute → observe cycle. Capabilities are opt-in flags:

agents/base_agent.py — the loop, simplified
for step in range(max_steps):
    messages = self._compact_messages(messages)            # context circuit breaker
    response = await self._call_llm(messages, tools)   # decide
    tool_calls = self._extract_tool_calls(response)
    if not tool_calls:
        break                                          # model says: done
    for name, args in tool_calls:
        result = await handlers[name](args)            # act
        messages.append(tool_result(result))               # observe → next turn

read_file · list_files · grep_code — inspect the codebase before changing it. Output is bounded so a worker can't pull an unbounded blob into context.

run_tests · run_lint — the act → observe loop. Runs only the profile's verify_cmd/lint_cmd, never an arbitrary shell string the model invents.

edit_file — surgical anchored search/replace with a whitespace-tolerant fallback when the model's anchor drifts by indentation alone.

generate_mock_data — deterministic synthetic CSV/JSON/JSONL fixtures so Data/ML engineers test pipelines without production data.

enabling tools is one flag — capabilities compose
await self.run_tool_loop(
    user_message=brief,
    tool_handlers={"write_file": write_handler},
    read_tools=True,    # inspect before patching
    exec_tools=True,    # run_tests / run_lint (profile-fixed)
    edit_tools=True,    # surgical edit_file
    mock_tools=True,    # generate_mock_data fixtures
)
Grounding, concretely. Before QA spends a test run, core/artifact_quality.phantom_imports statically catches a hallucinated import and triggers a targeted fix — a cheap reality check that saves a whole loop.
③ Planning, realized

--adaptive: plan · re-route · self-check

// THEORY

“Write the recipe from the goal, then rewrite it when a step fails — within a budget.”

// AGENTFORGE

lead._plan_phases → _replan_after_phase → _verify_goal_met, each bounded by a replan budget and a hard phase cap.

agents/lead.py — re-route only on a real signal, only within budget
if self._replan_budget <= 0:
    return []                                   # out of budget → stay the course
if not (outcome["quality_debt"] or outcome["escalated"]):
    return []                                   # no signal → no replanning
# otherwise: ask the Lead to insert ONE focused follow-up phase, then decrement the budget

Circuit breaker. Within a single loop, BaseAgent._compact_messages drops the oldest complete tool exchanges (a sliding window preserving tool_use/tool_result adjacency) once messages exceed AGENTFORGE_CONTEXT_CHAR_BUDGET — graceful degradation instead of an overflow error.
⑥ Guardrails, realized

The brakes, by default

trust

Independent review

Reviewer reads real files, returns a structured verdict. A missing verdict defaults to reject.

focus

Scope lock + Known Gaps

Out-of-scope finds → reports/known_gaps.md, deferred not absorbed.

ask

Escalation safe-pause

AGENTFORGE_ESCALATION_TIMEOUT — defers to the deploy gate if no operator answers.

ship

Deploy gate

verify → human go/no-go → commit. Commit opt-in; push never automatic.

Brakes you can name: replan budget · hard phase cap · revision cap (3, then accept-with-debt) · context circuit breaker · profile-fixed execution (no arbitrary shell) · sandboxed file I/O (rejects ../ traversal) · diff-only re-reviews (core/diffs.unified_diff).
⑦ Evaluation, realized

Two layers: deterministic tests + an LLM judge

// THEORY

“Deterministic tests check plumbing; a judge model scores whether the output is actually good.”

// AGENTFORGE

tests/ (faked LLM, 250 deterministic) + evals/judge.py — an LLM-as-a-Judge that rubric-scores artifacts with a small model.

A scenario opts in by declaring a rubric; the judge's core is pure and the LLM call is injected, so CI stays deterministic. Run it with run_evals.py --judge:

evals/scenarios/intake_requirements.yaml — rubric (excerpt)
judge_target: docs/requirements.md
judge_threshold: 0.7          # pass if weighted score >= 0.7
rubric:
  - key: completeness
    description: All mandatory sections are present and substantive.
    weight: 2
  - key: clarity
    description: Requirements are specific and testable.
bash — opt-in, costs tokens, non-deterministic
export ANTHROPIC_API_KEY=sk-...          # or AGENTFORGE_LLM_PROVIDER=ollama
uv run python evals/run_evals.py --judge
Why this matters. Without the judge, a refactor can keep all 250 tests green while quietly making the PM's requirements vaguer. The judge turns “is the prompt still good?” into a tracked score — the bridge between deterministic plumbing and real output quality.
